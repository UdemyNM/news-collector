# add-feature

機能を足すときの手順。実装より先に「どこを変えるか」と「テスト」を決める。

## 手順

### 1. 変更するファイルと関数名を先に決める
コードを書く前に、次を決めてユーザーに伝える。

- 変更するファイル（実装側とテスト側の両方）
- 追加・変更する関数やメソッドの名前、引数、戻り値
- 迷う点（例: 0 件のときの扱い）があれば、ここで確認する

CLAUDE.md の「フォルダ構成」に沿って置き場所を選ぶ。
決めた内容は 1 つの表か箇条書きにまとめ、書き始める前に見せる。

### 2. テストを先に書く
- 手順 1 で決めたテストファイル（`tests/test_*.py`）に、追加する機能のテストを書く。
- 正常系に加え、境界（0 件、空、None など）も書く。
- ネットワークはモックにする（`tests/sample_data.py` の fixture を使える）。
- この時点では、実装は書かない。

### 3. テストが失敗することを確認する
- pytest を実行し、書いたテストが失敗することを確認する。
- 失敗の理由が「機能が未実装だから」であることを、出力で確かめる。
  構文エラーや import の誤りで落ちているなら、テストを直してやり直す。
- 最初から通るテストは、何も確かめていない。見直す。

### 4. 実装する
- 手順 1 で決めたファイルと関数名のとおりに実装する。
- テストを通すのに必要な範囲だけ書く。頼まれていない整理や名前の変更はしない。

### 5. テストを通す
- pytest を実行し、追加したテストと既存のテストがすべて通ることを確認する。
- 落ちたら、実装を直す（テストを緩めて通さない）。

### 6. 結果を報告する
- 変更したファイルと関数名
- 手順 3 の失敗の出力と、手順 5 の成功の出力
- 動かせなかった確認があれば、その理由

## 注意
- テストの実行は、仮想環境（`.venv`）の Python で行う。
  ただし GitHub Actions 上など `.venv` がない環境では、`.venv` を作らず、
  インストール済みの `python -m pytest` をそのまま使う。
- コミットや PR は、頼まれたときだけ行う。`main` には直接 push せず、ブランチを作って PR にする。
